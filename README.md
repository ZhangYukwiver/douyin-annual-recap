# 抖音个人总结

这是一个完全本地、隐私优先的抖音个人记录工具。它通过独立浏览器读取本人账号当前可见的观看历史、点赞列表和收藏列表，再基于已有记录生成个人总结。

默认同步不使用抖音开放平台、外部 AI、Coze 或私有接口签名。另有一个仅限本机的实验功能：观看历史直接请求接口，点赞和收藏由无界面浏览器自动加载到末页；观看历史使用 `mafqla/douyin-api` 固定提交中的签名代码。标题、作者、封面、Cookie 和本地总结都不会发送到外部分析服务。

## 当前流程

1. 双击项目根目录中的 `抖音年度回顾.app`。这个旧文件名暂时保留，打开后会在后台启动本地采集器和 Web 页面，无需终端或配对码。
2. 首次使用时，在打开的独立浏览器中登录自己的抖音账号。
3. 在“数据源”点击“读取记录”。采集器会自动依次定位观看历史、点赞和收藏三个主页面，并持续滚动到网页接口返回末页。
4. “总结”页面立即使用全部已读取记录生成封面和 8 张全屏卡片，继续展示数量、作息、月份、常见创作者、显式话题、音乐、时长、列表交集和代表内容。

个人总结不需要先选择年份，也不要求记录具有行为时间。没有日期的记录仍会参与总结；应用不会用发布时间或采集时间伪造观看、点赞或收藏时间。

## 为什么还会滚动页面

抖音网页接口由抖音自己的页面脚本携带当前登录状态和签名发起。采集器只监听这些网页响应，不直接伪造 Cookie、`a_bogus`、`X-Bogus` 或其他私有签名。

因此自动同步需要在正确列表的真实可滚动区域中滚动，触发网页加载下一批数据，直到接口明确返回末页。若页面无法继续滚动、游标不前进或响应重复，本次列表会标记为不完整，并保留已有完整数据。

## 实验性无界面增量读取

该路径启动无界面的 Chrome，复用专用 Profile 的登录态，不弹出窗口，也不需要手动打开或滚动列表。首次运行会读取全部可见记录；成功全量读取后，再次运行只读取到本地已知记录为止，并把新增观看、点赞和收藏合并进原记录。观看历史逐页直接请求接口；点赞和收藏由抖音页面运行时生成当前签名并在后台自动滚动。取消点赞、取消收藏等删除不会在增量读取中移除本地旧记录。

先安装并离线检查固定版本签名器：

```bash
npm run direct:setup
npm run direct:check
```

签名器来自 `mafqla/douyin-api@42987a1`，安装时逐文件校验 SHA-256，并保存在已忽略的 `.local-data/direct-signer/`。其签名子进程在 macOS 下禁止网络、禁止写文件，且 Node 只能读取签名器目录和本项目的最小运行入口。上游许可文件随安装内容保留。

连接采集器后，在“数据源”点击“无界面读取新记录（实验）”。首次读取要求三个列表都到达末页；增量读取要求三个列表都到达本地已知边界或末页，之后才会一起保存。遇到游标异常、重复页、401、403、429 或非零平台状态时不保存本次不完整结果。观看日期优先读取响应中的逐作品 `aweme_date` 映射，并兼容 `history_info.view_time`；两者都缺失时保持为空，不会使用发布时间或采集时间替代。

这是未经抖音公开文档承诺的私有接口，可能失效或触发账号风控。当前仅用于本机测试账号验证，不应作为公开、多用户或商业服务。

## macOS 一键启动

- 保持 `.app` 与本项目在同一目录，不要单独移到“应用程序”。
- 首次打开时允许访问“文稿”文件夹。
- 浏览器刷新后如需重新连接，再次双击 `.app`。
- 从 Dock 退出该应用会停止它启动的本地服务。

修改启动脚本后可重新生成应用：

```bash
npm run app:mac
```

## 开发方式

安装依赖并分别启动采集器与 Web 页面：

```bash
npm install
npm run collector
```

另开一个终端：

```bash
npm run web
```

打开 `http://localhost:8081`，在“数据源”填写采集器显示的 8 位一次性配对码。连接只读取现有本地快照；只有点击手动监听、读取记录或换账号时才会打开独立浏览器。

## 采集方式

- **自动同步**：依次定位观看历史、点赞和收藏三个主页面，持续滚动并合并唯一记录，直到各接口明确返回末页。
- **手动监听**：打开独立浏览器后，由你自行浏览页面。采集器只保存监听期间实际出现的受支持网页响应，不验证列表是否完整。
- **换账号**：清除独立浏览器中的抖音会话和本地记录，然后等待你登录另一个账号。
- **文件导入**：JSON / ZIP 仍作为备用数据源。总结时使用导入文件中的全部有效记录。

自动同步不会绕过验证码或安全提示。抖音页面结构或响应格式变化时会返回明确错误，不会把无法读取误报为空列表。

## 本地接口与隐私

- 本地服务默认监听 `127.0.0.1:4765`。
- `/v1/health` 用于健康检查，`/v1/pair` 使用一次性配对码，`/v1/sync` 启动默认页面同步。
- `/v1/experimental/records-direct` 只允许本机回环连接，启动实验性观看历史直读及点赞、收藏无界面采集。
- 12 小时会话 Token 只保存在应用内存和请求头中，不进入 URL 或本地存储。
- 独立浏览器配置保存在 `.local-data/browser-profile/`。
- 直接读取模板保存在 `.local-data/direct-history-template.json`，只含 UA、`webid` 和白名单参数，不含 Cookie、Token 或签名。
- 归一化记录保存在 `.local-data/records.json`。
- 原始响应、请求头、Cookie、签名和完整诊断 URL 不会写入记录文件。

App 中的“清除”只删除本地归一化记录，不会修改抖音账号里的观看、点赞或收藏状态。

## 手机连接

电脑和手机需位于同一可信局域网。电脑端显式启用 LAN 模式：

```bash
npm run collector -- --lan
```

应用中把服务地址改为采集器显示的局域网地址，例如 `http://192.168.1.20:4765`。Web 页面从局域网访问时还需传入实际页面来源：

```bash
npm run collector -- --lan --origin http://192.168.1.20:8081
```

LAN 模式仍使用一次性配对码和内存会话，但流量是局域网 HTTP，只应在可信网络使用。

## 当前边界

- Web 端提供个人总结、记录和数据源页面；原生端暂时保留记录和数据源。
- 总结描述的是网页或接口当前可见并成功读取的记录，不保证覆盖抖音服务端未提供的更早历史，也不做心理诊断。
- 仅使用记录中的显式作者、话题、音乐、时长和平台互动字段，不调用外部 AI 推测兴趣。
- 暂不包含直播或影视综历史、收藏夹深度遍历、截图分享、PNG / PDF 导出。
- 无界面采集不自动定时运行；仍属于可能随抖音页面变更而失效的实验能力。
