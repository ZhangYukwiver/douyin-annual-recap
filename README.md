# 抖音年度回顾

本项目通过本机独立 Chrome 会话读取本人的观看历史、点赞列表和收藏列表，并在本地生成年度回顾。不使用抖音开放平台接口、外部 AI 或 Coze。

采集器不会读取已有 Chrome 配置，不会导出 Cookie，也不会自行生成 `a_bogus`、`X-Bogus` 等签名。它只监听独立浏览器中由抖音网页自身发出的请求，将响应归一化为标题、作者、行为时间和视频链接。原始响应、请求头、Cookie、`msToken` 与签名参数不会写入记录文件或返回给移动端。

## 本机运行

在第一个终端启动采集器：

```bash
npm install
npm run collector
```

采集器会显示 8 位一次性配对码。在第二个终端启动应用：

```bash
npm run web
```

打开 `http://localhost:8081`，在“数据源”中填写配对码并连接。连接只读取已有的本地快照，不会启动浏览器或访问抖音网页。

## 年度回顾

- Web 端默认进入“年度”，窗口宽度达到 1024px 时显示封面和 8 张全屏卡片；更窄窗口保留“记录”和“数据源”入口。
- 默认选择最近一个有数据的完整自然年。仅有当前年数据时会显示“截至当前”。
- 年度筛选只接受 `platform_action` 和 `archive_action` 两类行为时间。发布时间和采集时间不会替代观看、喜欢或收藏时间。
- 每张卡片都会显示可分析状态和覆盖说明。无时间记录、部分采集和缺少 `videoId` 的内容不会被静默补齐。
- “留下来的内容”使用三份已采集列表的 `videoId` 集合交集，表示“已采集内容快照”，不是年度转化漏斗。
- 顶部隐私模式会替换标题、作者、无障碍文本和图片节点。报告不会把内容发送到外部服务。
- 原生端暂时保留“记录”和“数据源”页面，不显示年度报告。

## 实施方案

### 数据与接口

- 采集器继续监听专用 Chrome 中抖音网页自行返回的响应，仅借鉴 `douyin-api` 的端点和分页语义：观看历史、喜欢、收藏、收藏夹列表及收藏夹视频列表。
- 不接入参考项目的 Cookie、逆向签名、Flask 代理或 GPL 源码；也不复制 `WeChatDataAnalysis` 的代码、图片、样式和微信品牌素材。
- 采集快照使用 `schemaVersion: 2`，保留 `/v1/health`、配对和同步协议。客户端同时接受 v1/v2；v1 迁移保留全部记录并原子写回。
- 单条记录支持稳定 `videoId`、作者 ID/头像、行为时间来源、发布时间、封面、媒体类型、时长、音乐、话题、平台互动快照和观看进度。除核心字段外均为可选字段。
- `occurredAtSource` 只允许 `platform_action | archive_action | unknown`。年度筛选仅接受前两类；`publishedAt` 和采集时间不会替代行为时间。
- 归一化边界限制字符串长度、数组数量、数值范围和图片域名，只保存规范字段，不保存原始响应、请求头、Cookie、签名或完整诊断 URL。
- 重复视频按 `videoId` 合并：保留已有有效时间和稀疏元数据，合并话题，使用最新平台统计，并支持三种行为的跨类型关联。
- `buildAnnualIndex(records, options)` 单次遍历建立上海时区年份桶和全快照集合；`buildAnnualReport(index, year)` 生成确定性报告，年份切换不重新扫描原始记录。
- 报告直接消费当前 `DisplaySnapshot`。连接采集器时优先采集数据，否则使用当前会话导入的 JSON/ZIP，不新增年度网络 API。

### 报告结构

报告由封面和 8 张全屏卡片组成：

1. **年度总览**：三类有可靠时间的唯一视频数、活跃日、日期范围、全年热力图、峰值日和覆盖率。
2. **观看作息**：`7×24` 热力图、最活跃星期与小时、最早/最晚记录；少于 20 条或 14 个活跃日时不生成人格文案。
3. **月度轨迹**：12 个月观看、喜欢、收藏趋势和峰值月份；缺少可靠时间的系列明确标记为不可分析。
4. **创作者宇宙**：Top 创作者、不同创作者数、头部占比和探索度；未知作者单独计数，不进入排行。
5. **兴趣与声音**：仅使用平台话题、标题显式 `#话题`、音乐和视频时长，不生成推测词云或语义分类。
6. **留下来的内容**：基于全部已采集列表的两两交集和三者交集，明确命名为“已采集内容快照”。
7. **年度高光**：首条、末条、峰值日代表、最长视频和平台互动最高内容，全部使用稳定排序与真实封面降级。
8. **Bento 总结**：只复用前七页结果，不重新计算指标。

每张卡片均有 `ok | insufficient` 状态。部分采集、无时间记录和可比较 `videoId` 不足会在对应卡片直接说明。文案使用年度回顾语气，但不做心理诊断，也不把唯一视频条目描述成重复观看次数。

### 桌面体验

- Web 默认进入“年度”。宽度达到 1024px 时显示全视口报告与紧凑左侧导航；窄窗口展示扩大窗口提示并保留记录/数据源入口。
- 报告支持滚轮、上下方向键、PageUp/PageDown、Home/End、翻页按钮和页码导航；仅挂载当前页及相邻页。
- 顶部提供年份选择和隐私开关。隐私模式直接替换作者名、标题、无障碍文本和图片节点，不使用视觉模糊冒充脱敏。
- 使用 `react-native-svg`、Lucide 和原生 `Animated`。过渡控制在 200–350ms，并遵循 `prefers-reduced-motion`。
- 视觉使用中性浅色底、炭黑正文，以及观看青、喜欢红、收藏金三套语义色；真实封面失效或隐私模式下使用稳定占位。
- 记录和数据源页面继续保持受控宽度；原生端维持原有页面。

### 验证策略

- 三个核心抖音端点提供独立脱敏响应夹具，覆盖完整/稀疏字段、分页、异常 schema、不可信图片 URL 和重复元数据合并。
- 测试覆盖 v1→v2 迁移、原子写入、双版本客户端、上海跨年边界、闰年、无日期、partial、单行为、并列排行、稳定排序和无 `videoId` 交集降级。
- 确认发布时间不进入年度筛选，Bento 字段与来源卡片一致；150,000 条合成记录用于索引和报告性能基准。
- UI 验收覆盖默认年份回退、空数据、年份切换、键盘/滚轮翻页、隐私 DOM 脱敏、减少动效，以及 `1024×768`、`1440×900`、`1920×1080` 三档视口。
- 发布前运行 `npm run typecheck`、`npm test` 和 `npm run build:web`。

### 首版边界

真实账号只用于最终只读验收；报告始终展示可分析记录数、总记录数、实际日期范围和采集警告。首版不包括手机端年度页、直播/影视综历史、外部 AI、直连私有 API、截图分享或 PDF 导出。

## 采集方式

- **手动监听（默认）**：连接后点击“手动监听”，专用 Chrome 才会打开。登录后由你自行打开观看历史、喜欢和收藏页；采集器仅保存这些手动浏览过程中网页返回的归一化记录，结果会标记为可能不完整。
- **自动同步（可选）**：点击播放图标并确认后，采集器才会切换个人列表、滚动当前可见内容面板并加载分页。若无法确认当前标签页对应的可滚动面板，会停止该阶段并将结果标记为不完整，不会回退为整页滚动或全局“加载更多”点击。
- **换账号**：会清除专用 Chrome 的抖音会话和本地记录，然后打开专用浏览器进入手动监听，等待你登录新账号。

## 手机连接

电脑和手机需位于同一可信局域网。电脑端显式启用 LAN 模式：

```bash
npm run collector -- --lan
```

应用中把服务地址改为采集器显示的局域网地址，例如 `http://192.168.1.20:4765`。若使用 Web 页面从局域网访问，还需传入实际页面来源：

```bash
npm run collector -- --lan --origin http://192.168.1.20:8081
```

默认模式只监听 `127.0.0.1`。LAN 模式使用一次性配对码和 12 小时内存会话，但流量仍是局域网 HTTP；只应在可信专用网络使用。

## 本地数据

- 独立浏览器配置：`.local-data/browser-profile/`
- 归一化记录：`.local-data/records.json`
- 当前快照格式为 `schemaVersion: 2`；读取 v1 时会保留旧记录并原子迁移为 v2。
- 两者均被 Git 忽略。
- App 中的“清除”只清除归一化记录，不会修改抖音账号里的观看、点赞或收藏状态。
- “切换账号”会清除专用 Chrome 中的抖音登录状态、站点存储、缓存和本地采集结果，再进入手动监听等待新账号登录。
- JSON/ZIP 个人信息文件导入保留为备用入口，不是主数据源。

采集器不会绕过验证码或安全提示。抖音网页路由或响应结构变化时会返回适配错误，不会把缺失字段误报为空列表。

年度报告直接消费当前本地快照：连接采集器时优先使用采集结果，否则使用当前会话导入的 JSON/ZIP。首版不提供手机端年度页、直播/影视综历史、外部 AI、PNG/PDF 导出或截图分享。
